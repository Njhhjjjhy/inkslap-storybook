# Spacing

Inkslap's spacing system is built on an **8 px rhythm**. The live site's measured paddings — `8/16/24/32/40/48/60/70/80/128` — all sit on this scale. The documented system normalises those integer values; fluid `clamp()` expressions that collapse to sub-decimals at narrow viewports are explicitly out of scope.

---

## Component padding

Observed on the live site and normalised:

| Component | Padding | Source |
|-----------|---------|--------|
| Card CTA / small button | `8px 16px` | home `客製` button |
| Pill (upload, badge) | `6px 12px` | home upload pill |
| Primary CTA / standard | `16px 32px` | Services / About primary |
| Hero CTA / large | `20px 48px` | Services hero `Upload your logo` |
| Header buttons | `8px 12px` (normalised from clamp) | header login / register |
| Footer | `0 60px` (horizontal) | every page footer |
| Section padding (home) | `70px 0` or `80px 0` | FeaturedProducts / ProductCategories |
| Card content | `24px` | KeyFeatures cards |
| Modal | `24px` | login / register dialog |

The 8 px rhythm holds across every observed value. **Use the documented padding token for each component; do not invent ad-hoc values.**

## Border radius

Three tiers: tight (buttons), medium (cards, CTAs), pill (accent tags, search). The canonical radius for a primary button is **8 px**.

export const RadiusScale = () => {
  const radii = [
    { name: 'none', value: '0', use: 'plain inputs, dividers' },
    { name: 'xs', value: '4px', use: 'tiny chips, header buttons' },
    { name: 'sm', value: '6px', use: 'small pills (upload badge)' },
    { name: 'md', value: '8px', use: 'PRIMARY — standard buttons, CTAs' },
    { name: 'lg', value: '12px', use: 'cards, content blocks' },
    { name: 'xl', value: '16px', use: 'modals' },
    { name: 'pill', value: '999px', use: 'search input, accent pills' },
    { name: 'circle', value: '50%', use: 'icon buttons, swatches, avatars' },
  ];
  return (
    <div style={{ marginTop: '24px', display: 'grid', gridTemplateColumns: 'repeat(4, 1fr)', gap: '16px' }}>
      {radii.map((r) => (
        <div key={r.name} style={{ padding: '20px', backgroundColor: '#F9F9F9', borderRadius: '12px', textAlign: 'center' }}>
          <div style={{
            width: '80px',
            height: '80px',
            margin: '0 auto',
            backgroundColor: '#0099DE',
            borderRadius: r.value,
          }} />
          <div style={{ marginTop: '12px' }}>
            <code style={{ fontFamily: 'monospace', fontSize: '12px', background: 'transparent', color: '#040404' }}>radius-{r.name}</code>
          </div>
          <div style={{ fontFamily: 'monospace', fontSize: '12px', color: '#6C6C6C', marginTop: '4px' }}>{r.value}</div>
          <div style={{ fontSize: '11px', color: '#999', marginTop: '6px' }}>{r.use}</div>
        </div>
      ))}
    </div>
  );
};

## Container widths

The live site has **no fixed max-content container** — sections fill the viewport edge-to-edge. The documented system adopts the same pattern: page sections fill the viewport, with internal content constrained by component-level max-widths rather than a global wrapper.

| Surface | Max-width | Notes |
|---------|-----------|-------|
| Page section | viewport | fills edge-to-edge |
| Card grid (product catalogue) | viewport with `180px` left rail | sidebar + content layout |
| Login / register modal | `370px` | fixed |
| Cart order-total card | `280px` (right column) | fixed |

---

## Rules

| Rule | Detail |
|------|--------|
| 8 px rhythm | Every component padding and section spacing is a multiple of 8 (with one allowance for 4 px in micro-spacing). |
| Floor on fluid scales | If a `clamp()` or `vw`-derived value would resolve below 8 px on any breakpoint, clamp it at 8 px. |
| Primary radius is 8 px | All standard CTAs use `--radius-md`. Pills (search, accent tags) use `--radius-pill`. Avoid one-off values. |
| Component-level constraints | Constrain content with `max-width` on the component, not on a global container. |
